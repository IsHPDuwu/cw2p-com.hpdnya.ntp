# NTP 课表校时

电脑时间不准，导致课表倒计时和上下课提醒对不上？本插件通过网络时间服务器自动校正 Class Widgets 2 的课表时间，并支持根据学校铃声添加手动补偿。

**只调整课表时间，不修改电脑系统时间，界面上的系统时钟也不会改变。**


## 功能

- 自动获取网络时间，定期修正课表时差。
- 支持多个时间服务器，一个不可用时自动尝试下一个。
- 支持校铃补偿，让课表与学校铃声对齐。
- 查看同步状态、最近成功时间和当前偏移。
- 同步失败时保留已有偏移，稍后自动重试。

## 开始使用

1. 安装并启用插件后，打开插件设置页 **「NTP 课表校时」**。
2. 打开 **「接管课表偏移」**。此开关默认关闭。
3. 点击 **「立即同步」**，查看页面下方的同步结果。
4. 如果学校铃声与标准时间有差异，填写 **「校铃补偿」**。

启用接管后，主程序的时差偏移由插件自动管理，不能在主程序设置中直接修改。需要手动调整时，请使用插件内的校铃补偿。

## 校铃补偿怎么填？

单位是秒，可以填写正数或负数：

- **正数**：让课表提前。例如填 `10`，课表比网络时间提前 10 秒。
- **负数**：让课表延后。例如填 `-10`，课表比网络时间延后 10 秒。
- **`0`**：不额外补偿，直接跟随网络时间。

例如，学校铃声比标准时间晚 20 秒，可以填写 `-20`。

最终课表偏移由网络校时结果和校铃补偿共同决定，精确到整数秒；多次同步不会重复叠加。

## 设置说明

| 设置 | 说明 | 默认值 |
| --- | --- | --- |
| 服务器 | 按顺序尝试的时间服务器，多个地址用英文逗号分隔 | `time.cloudflare.com,ntp.aliyun.com,pool.ntp.org` |
| 同步间隔 | 自动同步的间隔，单位为分钟 | 30 分钟 |
| 校铃补偿 | 在网络时间基础上额外提前或延后 | 0 秒 |
| 单请求超时 | 每次网络请求的最长等待时间，不含地址解析 | 3 秒 |
| 最大往返延迟 | 网络延迟过大时不采用该次结果 | 1 秒 |
| 最大绝对 NTP 时差 | 电脑与网络时间相差超过此值时，拒绝自动修正 | 300 秒 |

通常保留默认设置即可。如果电脑时间相差几分钟以上，建议先校准系统时间，再使用插件。

## 常见问题

### 一直同步失败

先确认电脑能够联网。校园网、防火墙或安全软件可能限制网络校时所需的 **UDP 123 端口**；可以更换服务器，或联系网络管理员确认。

失败时插件不会清零已有偏移，会自动重试，也可以点击「立即同步」。

### 提示偏移已被锁定

其他插件或集控配置可能正在管理时差偏移。请先解除相应限制，再启用接管。不要让多个插件同时控制课表时差。

### 校时成功，但显示的时间没有变

这是正常现象。插件修正的是课表计算时间，用于倒计时和日程判断，不会改变电脑时间或界面系统时钟。

### 关闭插件后会怎样？

关闭接管或卸载插件后，会停止自动校时并释放对时差偏移的控制。如果偏移没有被其他来源修改或限制，会恢复接管前的数值；否则保留当前值。

## 注意事项

- 首次校时可能改变当前日程、倒计时和提醒触发时机，建议避开上下课的关键时刻操作。
- 网络时间仅用于日常课表校准，不适用于需要安全认证的计时场景。
## 配置接管与退出

启用前检查字段及 schedule 父锁，已有外部锁不抢。主线程同步执行解锁、写入、读回、finally 重锁，
同步 configChanged 回调受重入保护。退出仅解除本插件记录持有的锁；只有当前值仍匹配最后写入值且
无父锁时才恢复启用前值。恢复日志在写入前保存，异常重启不会把上次生成值当作原手动偏移。
外部修改/锁消失会暂停写入，需要关闭后重新启用。未接管成功绝不会解锁。
**宿主锁没有所有者或引用计数**：接管后其他插件再次锁同一字段无法区分，退出可能解除这把共享锁。
应避免其他插件同时控制该字段。宿主 save 会吞掉磁盘错误，因此不能保证断电恢复日志一定落盘。

## 网络与生命周期限制

普通 NTP 无认证，勿用于安全关键用途。UDP 123 被防火墙阻止时请检查网络策略或更换可访问服务器。
ntplib 支持 getaddrinfo 的 IPv4/IPv6，但仅尝试第一个解析地址；DNS 不受 socket 超时限制。
薄封装验证来源端点、原始请求时间戳、LI/stratum/模式、时间顺序、有限值、RTT、安全阈值；
按本机时间展开 NTP era（要求本机误差小于半个 era）。协议报文与偏移计算仍由 ntplib 实现。
工作线程协作取消，无 terminate、无主线程无限 wait；卸载后保留未结束线程直到 finished。
DNS 长时间阻塞时线程会继续存活，进程立即退出前仍应等待网络线程完成；不保证被强制结束时清理。
墙钟跳变/长调度间隔触发重同步；旧 generation 结果不写入。设置补偿时有效缓存立即重算，否则重新查询。
